# nanne 公開前法務・運用レビュー

調査日: 2026-08-16

## この文書の位置づけ

Issue #1 に基づき、nanne を日本で小規模に公開運用する前提で、法務・個人情報・通信の秘密・運用上の論点を整理した調査メモです。法律相談や個別案件の確定判断ではありません。公開前に、所轄の総務省総合通信局と、必要に応じて弁護士・弁理士へ事実関係を示して確認してください。

前提は、README にある次の v1 想定です。

- MIT License のOSS
- ブラウザで利用する、アカウント不要の招待URL方式
- 2〜数名のテキストリアルタイムチャット
- 公開タイムライン、検索、SNS、画像・動画・ファイル投稿は持たない
- 一定期間後に削除する
- 日本の個人事業主が公開運用する可能性がある
- 利用者が自分でホスティングする可能性がある

## 結論

日本で公開運用を始める前に、最低限、次を完了させるべきです。

1. 実際の運営者、料金・広告の有無、反復継続性、設備構成を整理し、電気通信事業に該当するかを総合通信局へ確認する。該当し、登録対象でない場合は、電気通信事業の届出を開始前に行う候補になる。
2. 運営者情報、問い合わせ先、プライバシー通知、利用規約、保存期間・削除方針を公開する。
3. メッセージ本文と通信メタデータへのアクセス権限、モデレーション・通報対応・法的要請への対応手順、ログの保存期間を先に決める。
4. Cloudflare、ホスティング、ログ、分析、エラー監視など、第三者へ送られるデータを棚卸しする。v1 は広告・アクセス解析タグを入れず、外部送信を最小化する方針が安全。
5. 招待URLの漏えい対策、レート制限、通報・ブロック、削除・緊急停止の手順を実装する。
6. OSS として配布する場合、各自のホスティング運営者が自分の利用者・設備・データ処理について責任を負うことをドキュメントに明記する。

「小規模」「無料」「Cloudflareを使う」だけで届出や個人情報対応が不要になるとは判断できません。一方、公開されたチャットは必ず届出が必要、とも断定できません。事業性、誰の需要に応じて提供するか、通信設備を誰が設置・運用するか、サービスの範囲を合わせて判断します。

## 1. 電気通信事業への該当性

### 調査結果

電気通信事業法は、他人の通信を媒介する電気通信役務を、他人の需要に応ずるために提供することを電気通信事業と定義しています。nanne のように、利用者Aのテキストを利用者Bへリアルタイムに届ける構成は、技術的には「他人の通信の媒介」に当たり得ます。

ただし、届出・登録の要否は、チャット機能の有無だけで決まりません。次を事実として整理する必要があります。

- 日本の利用者に対し、誰がサービスを提供するか
- 反復継続して運営するか、収益事業として行うか
- 自分で電気通信設備・回線を設置するか、第三者の設備上でアプリを運営するか
- 誰の通信を、誰に向けて、どの範囲で媒介するか
- 利用者が不特定多数か、招待された少人数だけか
- 外部サービスがデータを保存、処理、監視するか

個人のローカル開発、試験、自己利用が直ちに届出対象になるわけではありません。しかし、日本で継続的に第三者へ公開運用するなら、対象候補として事前確認するのが妥当です。

### 登録と届出

法9条は原則として登録を定めつつ、設備の規模・区域などが省令基準内の場合に登録を要しない仕組みを置いています。その場合でも、法16条の届出対象になる可能性があります。小規模なWebチャットだから自動的に届出、または自動的に対象外、とはいえません。

法164条の適用除外には、相手方が一者だけの場合、小規模な設備の場合、他人の通信を媒介せず電気通信回線設備を設置しない場合などがあります。少人数の招待チャットは、利用者数が少ないことだけを理由に第三の類型へ入るとは判断しにくく、実装と設備の確認が必要です。

また、適用除外に該当しても、電気通信事業法3条の検閲禁止、4条の通信の秘密の保護まで無くなるわけではありません。

### nanne v1 の暫定評価

nanne の想定は、次の理由から「日本で公開運用する前に総合通信局へ確認する」べきケースです。

- 利用者同士のメッセージをサーバー等で中継する
- 招待URLを通じて第三者に反復継続して提供する可能性がある
- 日本の個人事業主による運用が想定されている
- Cloudflare等の第三者インフラを利用する可能性がある

確認の結果、電気通信事業に該当し、法9条の登録対象ではない場合は、法16条に基づく届出を開始前に行う候補になります。届出対象かどうか、また登録が必要かどうかは、実際の設備構成と運用形態を添えて確認してください。

### 届出の実務

e-Gov の「電気通信事業の届出」は、法16条1項に基づく手続で、手数料はありません。案内上は事業開始前の提出で、個人・法人、電気通信回線設備の設置有無などにより入力・添付内容が分かれます。

- [電気通信事業の届出（e-Gov）](https://shinsei.e-gov.go.jp/recept/procedure/lists/procedureInformation?gtaTetCd=145181GA00001)
- [電気通信事業法（e-Gov）](https://laws.e-gov.go.jp/law/359AC0000000086)
- [電気通信事業参入マニュアル（総務省）](https://www.soumu.go.jp/main_content/000739290.pdf)
- [電気通信事業参入マニュアル［追補版］（総務省）](https://www.soumu.go.jp/main_content/000477428.pdf)

届出後にサービス内容を変える場合の手続も分かれます。

- 役務の種類等の変更報告は、変更後に提出する手続です。[e-Gov](https://shinsei.e-gov.go.jp/recept/procedure/lists/procedureInformation?gtaTetCd=145181GA00002)
- サービス区域や電気通信設備の概要の変更届出は、変更前に提出する手続です。[e-Gov](https://shinsei.e-gov.go.jp/recept/procedure/lists/procedureInformation?gtaTetCd=145181GA00004)
- 事業を全部廃止した場合は、廃止後に届出する手続です。[e-Gov](https://shinsei.e-gov.go.jp/recept/procedure/lists/procedureInformation?gtaTetCd=145181GA00007)

### Cloudflare・外部インフラ

Cloudflare、クラウド、ホスティングを利用することだけで、nanne の運営者が電気通信事業上の検討対象から外れるとはいえません。少なくとも次を図にして確認してください。

- アプリ、データベース、ログ、バックアップを誰が管理するか
- 通信設備・回線設備を誰が設置しているか
- メッセージ本文・IPアドレス・アクセスログを誰が見られるか
- データ保存地域と、海外事業者への委託・移転の有無
- Cloudflare等の外部サービスが、サービス提供に必要なデータ以外を取得するか

第三者インフラの利用は、届出の要否と個人情報の委託・第三者提供・外国移転の論点を分けて確認します。

## 2. 通信の秘密とログ・モデレーション

電気通信事業法3条は検閲を、4条は通信の秘密の侵害を禁止しています。保護対象は、メッセージ本文だけでなく、通信の当事者、日時、識別情報など、通信の意味を推知できるメタデータを含み得ます。

v1 では、次の設計を文書化してください。

- メッセージ本文へアクセスできる管理者を最小限にする
- 通報対応、障害調査、法的要請、緊急対応の目的ごとにアクセス条件を分ける
- 通常運用で本文を読まない場合と、例外的に確認する場合を利用者へ明示する
- 何を、どの期間、どの理由でログ保存するかを決める
- 管理者アクセスを記録し、不要になったデータを削除する
- 捜査関係事項照会や削除要請を受けた時の保存・開示判断を一本化する

「規約に、運営者が全メッセージを自由に閲覧できると書けばよい」という設計は避けます。必要性、範囲、利用者への説明、アクセス権限、保存期間を限定してください。

## 3. 個人情報、Cookie、外部送信

### 個人情報保護法

個人情報保護法は、事業者の規模が小さいことだけで適用対象から外れるものではありません。ニックネーム、メールアドレス、IPアドレス、Cookie・端末識別子、メッセージ本文は、他の情報と容易に照合できるかなどにより、個人情報または個人関連情報になり得ます。

v1 の公開前に、少なくとも次をプライバシー通知に書きます。

- 取得するデータの種類
- 利用目的
- 保存期間または削除基準
- クラウド・ログ・監視サービスへの委託
- 海外事業者・外国サーバーが関係する場合の説明
- 開示、訂正、削除、問い合わせ窓口
- 事故時の連絡方針

個人情報の安全管理措置、不要となったデータの消去、漏えい時の対応も必要です。プライバシーポリシーという名前のページ自体が常に法律上の書類として要求されるという意味ではありませんが、利用目的等を利用者に通知・公表するため、公開サービスでは実質的に必須の文書です。

- [個人情報保護法ガイドライン（通則編、個人情報保護委員会）](https://www.ppc.go.jp/personalinfo/legal/guidelines_tsusoku/)
- [個人情報保護法 FAQ（個人情報保護委員会）](https://www.ppc.go.jp/personalinfo/faq/APPI_QA/)

### Cookie・外部送信

外部送信規律は、Cookieという名前の技術だけを対象にするものではありません。Webサイトやアプリが端末に送信指令を出し、利用者に関する情報を外部へ送る場合に、サービスの種類、送信先、情報の内容、例外要件を確認する必要があります。

nanne v1 では、広告タグ、第三者アクセス解析、不要なトラッキングSDKを入れず、Cloudflare・エラー監視等の必要サービスだけを一覧化するのが安全です。外部送信の対象サービスに当たる場合は、通知、容易に知り得る状態、同意・拒否手段などを個別に確認します。

- [外部送信規律に関する総務省FAQ](https://www.soumu.go.jp/main_sosiki/joho_tsusin/d_syohi/gaibusoushin_kiritsu_00002.html)

## 4. 利用者投稿、違法・権利侵害コンテンツ

v1 は、公開タイムラインや不特定多数向けの投稿サービスを前提にしていないため、大規模なプラットフォーム事業者向けの義務がそのまま発生する可能性は高くありません。ただし、これは違法・権利侵害コンテンツへの対応が不要という意味ではありません。実際に誰が受信できるか、部屋を公開できるか、サービス規模がどう変わるかで評価は変わります。

開始時点で、少なくとも次を用意します。

- 通報窓口と、削除・ブロック・停止の判断基準
- なりすまし、嫌がらせ、脅迫、個人情報、著作権侵害、性的画像等の緊急エスカレーション
- 利用者からの削除要請・開示要請の受領方法
- 重大事故時のログ保存と関係機関への相談手順
- 招待URLの無断共有、連投、DoS、アカウント・端末の不正利用への制限
- 未成年者の利用可否、保護者対応、禁止行為の方針

現行の「特定電気通信による情報の流通によって発生する権利侵害等への対処に関する法律」に基づく大規模事業者向け制度は、指定対象となる大規模事業者を中心としたものです。2〜数名の招待チャットが直ちにその指定対象になるとは考えにくいものの、公開範囲を広げる場合は再評価します。

- [特定電気通信による情報の流通によって発生する権利侵害等への対処に関する法律（e-Gov）](https://laws.e-gov.go.jp/law/413AC0000000137?occasion_date=20260625)

## 5. v1 の対応優先度

| 優先度 | 開始前に行うこと |
| --- | --- |
| 必須候補 | 総合通信局への事前確認、該当する場合の電気通信事業の届出 |
| 必須候補 | 運営者情報、問い合わせ先、プライバシー通知、利用規約、保存・削除方針 |
| 必須候補 | 通信の秘密を守る管理者権限、ログ、バックアップ、削除、事故対応 |
| 必須候補 | Cloudflare・ホスティング・監視・ログのデータフローと委託先の棚卸し |
| 強く推奨 | 通報、ブロック、招待URL失効、レート制限、緊急停止 |
| 強く推奨 | 第三者広告・解析タグなしで開始し、外部送信を最小化 |
| 強く推奨 | OSS利用者向けに、ホスティング運営者が法務・運用主体になることを説明 |
| 将来対応 | 有料化、広告、公開ルーム、検索、画像・動画・ファイル、海外展開、利用者数増加に伴う再評価 |
| 将来対応 | 年齢確認、本人確認、専門的なコンテンツモデレーション、商標登録 |

## 6. 未解決事項

総合通信局または専門家へ相談する際は、次の回答を添えてください。

- 有料・無料、広告・寄付・サブスクリプションの有無
- 想定利用者数、公開範囲、招待URLの発行者
- 自前設備か、Cloudflare等のクラウド上のアプリか
- サーバー、データベース、ログ、バックアップの所在
- メッセージ本文を誰がどの目的で閲覧できるか
- IPアドレス、Cookie、端末情報、アクセス解析の取得内容
- 未成年者の利用を許可するか
- 利用者間の通信を誰に向けて媒介するか
- 一定期間後の削除が本文、ログ、バックアップのどこまで及ぶか
