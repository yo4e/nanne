# 法務・公開前調査の履歴

このディレクトリは、`nanne` の公開前に行った法務・ネーミング調査のうち、後続の方針変更やリポジトリ更新によってそのままではマージしづらくなった調査結果を、履歴として残すための場所です。

## 2026-08-18 snapshot

`docs/research/2026-08-18/` には、当時の PR #3 / #4 でまとめた一次資料ベースの再調査を保存しています。

含まれる内容:

- `JAPAN_TELECOM.md`: 日本で公開運用する場合の電気通信事業法の判断軸、登録・届出・適用除外の整理
- `LEGAL_REVIEW.md`: 公開前の法務・運用チェック
- `NAMING_REVIEW.md`: `nanne` 名称の初期スクリーニング
- `TELECOM_FILING_SCHEDULE.md`: 届出条件と公開スケジュールへの影響の整理
- `EMBEDDING_LEGAL_REVIEW.md`: self-hosted / 共通バックエンド / ホワイトラベル / 外部リンクの提供主体の整理

これらは、PRをそのまま現在の `main` にマージしたものではなく、**当時の調査スナップショット**です。法令・手続・サービス構成は変わり得るため、現在の運用判断や公開手順としては扱いません。

## 現在の扱い

現在の `nanne` v1 は、まず MIT License のOSSとして公開し、各利用者が自分の Cloudflare Workers 環境へ self-host できる状態を一区切りとしています。

現時点では、公式ホスト版の本格的な一般公開、独自ドメイン、広告・スポンサー等による収益化は進めません。これらを始める場合は、その時点の実際のサービス構成・運営形態・設備構成・収益性をもとに法務・運用を再確認します。

現在の判断・手順は、次を優先してください。

- `docs/JAPAN_TELECOM.md`
- `docs/LEGAL_REVIEW.md`
- `docs/EMBEDDING_LEGAL_REVIEW.md`
- `docs/SELF_HOSTING.md`
- Issue #11「将来検討: 公式ホスト版・独自ドメイン・広告収益化と公開運用」

## なぜPR #3 / #4をそのままマージしないか

PR #3 / #4 は、いずれも古い `main` から分岐した調査PRで、その後に `nanne` 本体の実装、Cloudflare Workersでの公開、24時間固定TTL、セルフホスト手順、現時点では電気通信事業の手続を保留する方針などが追加されました。

そのため、古いPRを競合解消して丸ごと採用するよりも、調査成果を履歴として保存し、現在の方針は現在のドキュメントとIssueで管理するほうが、事実関係と意思決定を混ぜずに済みます。

このアーカイブは、将来公式ホスト版・収益化・埋め込み提供を再検討するときの出発点として使います。
