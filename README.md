# nanne

**「なんね？」から始まる、極小の一時チャット。**

`nanne` は、URLをひとつ渡すだけで、知らない人同士でもすぐ話せる小さなチャットサービスの構想です。

名前は北九州などで使われる方言の「なんね？」から。標準語なら「なに？」「どうしたん？」くらいの、会話の入口になる短い呼びかけです。

## Concept

Discordのサーバーを作るほどではない。LINEを交換するほどでもない。アカウントを作って、プロフィールを書いて、フォローし合う必要もない。

ただ、少し話したい。

`nanne` は、そのための**極小の通信路**を目指します。

```text
部屋を作る
   ↓
URLを相手に渡す
   ↓
入る
   ↓
話す
   ↓
しばらくしたら消える
```

サービス側が人間関係を囲い込むのではなく、必要な時間だけ小さな場所を貸すイメージです。

## 最初の姿

初期版は、できるだけ機能を増やさない。

- アカウント不要
- 招待URLで入室
- 2人〜少人数のルーム
- テキストチャットのみ
- リアルタイム送受信
- ルーム検索なし
- 公開タイムラインなし
- フォロー / フレンド機能なし
- 画像・動画・ファイル送信なし
- 既読・リアクション・スタンプなし
- 一定期間後に履歴を自動削除
- モバイルでもすぐ使える最小UI

「チャットサービスを作る」と聞いて想像する機能の多くを、意図的に持たないところから始めます。

## 想定する使い方

- イベントや即席チームの一時連絡
- 個人売買などで、本名のSNSを交換せず話したいとき
- 取材・創作企画・共同作業の短期連絡
- その場だけの相談や打ち合わせ
- 「ちょっとこのURLで話そう」が一番早い場面

恒久的なコミュニティを作る道具ではなく、**会話のための仮設小屋**です。

## Design principles

### Small

機能を足すより、なくても成立するものを削る。

### Temporary

会話を永遠に蓄積しない。保存期間は短く、利用者にも分かる形にする。

### Low friction

登録やプロフィール作成より先に話せることを優先する。

### Private by default

ルームは検索・一覧公開せず、招待URLを知っている人が入る形を基本とする。

### Boring technology is welcome

目的は新しいチャット技術を発明することではなく、**軽率に使える小さな通信サービスを、堅実に運用すること**。

## Non-goals

少なくとも初期段階では、以下を目指しません。

- SNS化
- 大規模コミュニティ
- 無限履歴
- AIチャット
- 音声 / ビデオ通話
- ファイルストレージ
- 高機能なユーザー管理
- 広告やエンゲージメント最大化

## Legal / operation

`nanne` は利用者同士の通信を扱うサービスになるため、公開前に日本の電気通信事業法を含む必要な手続・運用要件を確認し、該当する届出等を行います。

あわせて、少なくとも次を公開前チェック項目とします。

- 電気通信事業に関する手続
- プライバシーポリシー
- 利用規約
- メッセージ保存期間と削除方針
- 不正利用・通報・ブロック等の最低限の安全設計
- ログやアクセス情報をどこまで保持するか

「軽率に作る」は、法務や安全まで軽率にするという意味ではありません。

## Development direction

まずは一つのルームで人間同士が話せる最小形を作る。

その後、実際に使いながら、必要だったものだけ追加します。

```text
v0: concept
 ↓
v1: URLを作る / 入る / 話す / 消える
 ↓
vNext: 実運用で本当に必要だったものだけ
```

完成形を先に決めすぎず、**「これだけなら今すぐ使える」最小点を探す**プロジェクトです。
